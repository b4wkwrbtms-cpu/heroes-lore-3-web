# 영웅서기3 퀘스트 안내

지원 대상은 LGT `PD119037`의 2009-03-10 실행 파일과 기존 게임플레이 패치입니다.
게임 화면 아래의 고정 안내 줄에 수락한 퀘스트와 목적지 방향을 표시합니다.
가로 화면에서는 왼쪽 조작부 위에 위치하며, 미니보스 체력바 위에 겹치지 않습니다.
`퀘스트 ▾`를 누르면 원문 목표 지역, 처치·수집 수량과 설명을 보거나 다른 퀘스트를 선택할 수 있습니다.
`접기`는 표시를 작게 만들며, 선택은 이 게임의 PID에만 저장됩니다.

- 같은 맵의 살아 있는 목표 몬스터: 원형 표식.
- 다른 지역: 현재 스토리 조건에서 이용 가능한 출구에 마름모 표식.
- 화면 밖의 목표: 화면 가장자리 방향 화살표.
- 완료 조건에 맞는 NPC 이벤트가 확인되면 해당 위치 또는 귀환 출구 안내.
- 경로를 확인할 수 없으면 원문 목표 지역과 `연결 경로 확인 필요` 표시.

자동이동/자동대화는 실행하지 않습니다. 벽·장애물을 포함한 보행 경로는 검증하지
않았으며 화살표는 목표/출구의 방향을 가리킵니다. 대화, 메뉴, 로딩, 일시정지에서는
안내를 숨깁니다. 이노티아와 영웅서기 제로에서는 안내 객체를 만들지 않습니다.

한 번의 불완전한 필드 읽기는 50ms 뒤 다시 확인하며, 같은 씬·캐릭터·진행 중
퀘스트라는 조건이 확인될 때만 마지막 표시를 최대 750ms 유지합니다. 맵 이동,
대화·메뉴 진입, 퀘스트 완료는 다음 샘플 주기를 기다리지 않고 이전 표식을 지웁니다.
안내 줄의 높이는 일정해서 숨김·복귀 때 게임 화면 크기가 바뀌지 않습니다.
표식도 원작 화면 위쪽 64픽셀과 아래쪽 56픽셀을 피해 배치합니다.

## 근거와 검증

게임 메모리가 진행 상태의 유일한 기준입니다. 안내는 메모리·세이브·키 입력을
수정하지 않습니다. 원문은 사용자가 가져온 ZIP/JAR의 `res/dat/quest_??_dat`와
`res/event/e????_scn`에서 읽습니다. 원작 데이터/바이너리를 배포 파일에 넣지 않습니다.

| 원작 루틴/위치 | 사용한 의미 |
| --- | --- |
| `0x3f470`, `G+0x9e00 → +0x48/+0x5c` | 수락 퀘스트 목록/개수 |
| `G+0x9f98`, `G+0x9e98` | 퀘스트/스토리 조건 플래그 |
| `0x54188`, `0x5439c`, `0x5e46c` | 캐릭터별 퀘스트 문구/메인·서브 구분 |
| `0x38314`, `G+0xa266…0xa2b1` | 처치 목표, 필요 수량, 현재 수량, 연결 퀘스트 |
| `G+0xa2b3…0xa30d` | 수집 목표와 연결 퀘스트; 수량은 현재 가방에서 읽음 |
| `0x51f90` | 씬 원본의 트리거/행동/문자열 구획 |
| `0x52148`, `0x3beac` | 첫 번째 조건 충족 분기, 레벨/돈/아이템/플래그 검사 |
| 행동 40 | 씬 이동. 맵 리소스 ID와 씬 ID를 혼동하지 않음 |

`G = 0x01503ab0`. 순수 이동 명령 하나로 구성된 이벤트만 지역 연결로 사용합니다.
선택지·연출·상태 변경이 섞인 이동이나 알 수 없는 조건은 추측해서 경로에 넣지 않습니다.
고정 주소는 PID와 실행 파일 지문 두 곳을 검사한 후에만 읽습니다.

개발 중 원래 ARM Thumb 루틴을 실행해 수락, 목표 등록, 처치 5회, 완료 및
비교 조건의 동작을 확인했습니다. 원작 리소스 바이트와 메모리 덤프는 저장소에
추가하지 않습니다. 공개 테스트는 직접 만든 입력만 사용합니다.

`node --test wie-web/tests/*.test.cjs`는 퀘스트 상태 변화, 출구 잠금, 목표 몬스터,
캐릭터 변경, 메뉴/로딩, 타 게임 격리, HUD 접기, 250ms 갱신 제한 및 종료 정리를
검증합니다.
